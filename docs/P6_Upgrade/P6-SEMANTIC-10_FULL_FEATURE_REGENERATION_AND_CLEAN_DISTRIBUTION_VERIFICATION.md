## 1. Regeneration Mechanism Investigation

### How the Refresh Pipeline Works

The production refresh (`src/app/api/refresh/route.ts`) operates as follows:

1. **Date scope:** Only processes **today's business date** (`getBusinessDate()`)
2. **Coin scope:** All active coins (`isActive = true`)
3. **Data collection:** Fetches fresh klines, OI, funding, CoinGecko data for each coin
4. **Feature calculation:** Calls `runFeatureEngine()` with current code (continuous derivative)
5. **Feature persistence:** Upserts to `features` table with conflict on `(coinId, date, versionId)`
6. **Historical features:** NOT touched — preserved as immutable historical records

### Why Only Today's Features Are Regenerated

This is **intentional architecture**, not a bug:

- **Historical features** represent what was actually computed on that date using the code available at that time
- **Today's features** are always regenerated with the latest code
- **P6 snapshots** use the latest features for current health calculation
- **The "mixed state"** across the full features table reflects the natural evolution of the codebase

### Key Finding

The features table contains 1133 records spanning Jul 31 – Sep 1. Only the 49 most recent records (Sep 1) are regenerated by the current continuous implementation. The remaining ~1084 historical records retain their original step-function values. **This is correct behavior.**
